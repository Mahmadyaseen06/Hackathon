# Debugging & Gotchas Notes

- **XGBoost libomp runtime on macOS (Apple Silicon)**: `xgboost` requires `libomp.dylib` which was missing. Resolved by running `brew install libomp` and setting `DYLD_LIBRARY_PATH="/opt/homebrew/opt/libomp/lib:$DYLD_LIBRARY_PATH"` / symlinking `/opt/homebrew/lib/libomp.dylib`.
- **Port 8000 conflict**: Port 8000 is occupied by a background uvicorn process (`trace-x`). Configured AI Placement Predictor FastAPI backend to run on port `8001` and Vite proxy to route `/api` requests to `http://127.0.0.1:8001`.
- **SHAP TreeExplainer expected_value dimension**: In recent SHAP binary classifier outputs, `explainer.expected_value` can be returned as a 1D array or list rather than scalar float. Handled with `float(np.ravel(exp_val)[0])`.
- **React component missing useState import**: `StudentDiagnostics.jsx` used `useState` without explicit import from `'react'`, throwing a runtime ReferenceError. Fixed by adding `import React, { useState } from 'react';` and wrapping the main application in a React `ErrorBoundary`.
- **FastAPI root route 404**: Accessing `http://127.0.0.1:8001/` returned `{"detail": "Not Found"}` because only `/api/*` endpoints were registered. Added `@app.get("/")` index route providing navigation links to `/docs`, `/api/health`, and frontend URL.
- **Unlisted skills defaulting to 5.0 (Fake Job Ready bug)**: In `ml/pipeline.py`, unlisted skills were defaulting to 5.0 and aptitude to 70.0, causing students with only "basic python" to be falsely classified as "Ready". Fixed by defaulting unlisted skills to 0.0, parsing string skill levels, and applying reality-check penalty caps.
- **Missing `success: true` in `/api/interview/start`**: `static/interview/index.html` threw an unhandled start error because the endpoint returned session details without an explicit `success: True` flag. Added `success: True` and `round` metadata.
- **Browser subagent Playwright driver 404**: Playwright 1.57.0 macOS arm64 driver download failed from Azure CDN. Handled with full automated test coverage in `tests/test_interview_and_strict_ml.py` and curl verification.
- **Interviewer Talking-Back & Multi-Round Pipeline**: Integrated local Ollama `llama3.2:3b` with browser SpeechSynthesis, Monaco sandbox test runner, Web Audio visualizer, live webcam proctoring HUD, and 3-round progression (Coding OA -> Tech Deep Dive -> Leadership STAR). Verified end-to-end with 17 passing pytest tests and live API execution.
- **TTS Voice Quality & Echoing Bug**: Fixed double-voice audio overlap by replacing fixed 2.8s transition timer with `utterance.onend` completion callback. Added 90ms audio buffer flush delay before `speak()`, microphone pause during synthesis to eliminate acoustic feedback, markdown text sanitizer (`cleanTextForSpeech`), and dynamic voice selector prioritizing natural voices (Google US English, Samantha, Daniel, Karen).
- **CSV Ingestion & Student Profile Synchronization**: Added manual multi-tier profile editor and CSV ingestion engine for both Students and TPOs. Configured numeric parser for aptitude, coding benchmarks, and communication ratings, with client-side CSV template generation and instant re-prediction triggers.
- **Stacked Meta-Learner, Project Defense & Job Intelligence**: Replaced soft voting with scikit-learn 5-fold CV `StackingClassifier` (RF + XGB + LGBM + GBDT -> LogisticRegression meta-learner) achieving 99.16% ROC-AUC, 96.37% Accuracy, and 97.88% F1. Added 4 engineered feature interactions (`skill_depth_ratio`, `coding_academic_balance`, `backlog_recovery_rate`, `practical_exposure_score`). Added zero-coding verbal "Project Defense & HR Communication" track bound to student projects. Added Live Developer Sync (GitHub/LeetCode 30-day consistency score), Cross-Job Aggregate Gap Matrix (`/api/jobs/matched`), and 4-tier actionable TPO mentor alerts.
- **Duplicate Quick Voice Q&A Tab Purge & Professional HR Self-Introduction Progression**: The student dashboard contained an obsolete `#section-interview` tab with static company circles that intercepted the 'Take Interview Now' CTA and bypassed the realistic interview room. Purged 393 lines of dead code and obsolete company selection cards from `static/student/index.html`, routed all interview entry points directly to `/interview`, and restructured the Project Defense & HR Interview track to start with a natural executive self-introduction ('Tell me about yourself') followed by dynamic Ollama follow-ups into architecture defense, trade-offs, STAR behavioral scenarios, and company culture fit.
- **HackerRank-Style Dynamic Project Selection & Adaptive Interview Progression**: Replaced static pre-baked interview question arrays with dynamic real-time question generation. Introduced `_extract_project_mention` regex and profile cross-matcher in `interview/analyzer.py` that listens to candidate self-introductions, identifies specific project names (or prompts for their best project if unspecified), and feeds into `generate_adaptive_next_question`. The client UI updates `questions[currentQIndex + 1]` on every submission response, maintaining seamless HUD step progress while dynamically driving project architecture defense, concurrency trade-offs, and STAR leadership probing. Verified with live Ollama `llama3.2:3b` generation and 8/8 passing pytest tests.
- **Employability vs. Zero Job Matches Disconnect & Market-Grounded Retraining**: A student with high academic metrics (CGPA 9.25, 0 backlogs) but zero DSA and zero SQL was being predicted at 93.2% Employability by the ML model while matching 0 corporate jobs (17 stretch opportunities). Fixed by: 1) Updating `ml/dataset_generator.py` to model realistic zero-skill distributions and hard Online Assessment (OA) technical screening barriers (`oa_penalty = -3.2` when missing core DSA/SQL problem-solving); 2) Retraining the Stacked Classifier ensemble (`ROC-AUC: 0.9928`, `Accuracy: 95.8%`, `F1: 97.34%`); 3) Adding Rule 10 (OA screening gate) and Rule 11 (Market Feasibility Gate via `job_intelligence/market_evaluator.py`) to `_apply_strict_reality_checks`; 4) Preventing interview score blending from overriding hard reality check caps. Priya's score was honestly adjusted to 54.0% ("Needs Training") with transparent penalties clearly explaining the missing DSA OA prerequisite, harmonizing the Employability gauge with the Official Job Matches tab.
- **Sample Candidate CVs & 1-Click Live Demo Integration**: Created ATS-compliant PDF resumes using ReportLab: 1) `sample_cv_strong_candidate.pdf` (Aarav Sharma — B.E. CSE, CGPA 8.85, Razorpay backend intern, Distributed Task Scheduler, AWS cert, 380+ LeetCode) which achieves 99.2% employability and matches top SDE roles; 2) `sample_cv_needs_training.pdf` (Rahul Kumar — CGPA 8.92 but basic HTML/CSS only, 0 DSA) which demonstrates the OA gate failure and drops to 5.0% with explainable penalties; 3) `sample_tpo_batch_upload.csv` for 8-student institutional cohort onboarding on `/tpo`. Integrated one-click sample loader buttons directly onto `static/signup.html` for frictionless judge presentations.
- **Microphone Voice Capture Failure & God-Tier Audio Engine**: In Brave Browser and strict offline environments, `webkitSpeechRecognition` fails silently or triggers network errors because Google Cloud Speech services are blocked by Brave shields, and `navigator.mediaDevices.getUserMedia` was never called beforehand to prompt for microphone permission. Resolved by: 1) Initializing hardware microphone stream via `getUserMedia` with echo cancellation; 2) Connecting Web Audio API `AudioContext` and `AnalyserNode` to drive a real-time 18-bar Canvas frequency visualizer and RMS volume VU meter (dB readout); 3) Providing a resilient fallback to backend `/api/interview/transcribe-audio` using `speech_recognition`; 4) Integrating a 1-click **Live Demo Presets Tray** with 5 tailored technical answers (Intro/Distributed Scheduler, Architecture/LSM Engine, Raft Consensus, STAR Outage MTTR cut, Google Culture) so presenters never get stuck during live presentations; 5) Adding holographic interviewer persona states (`speaking`, `listening-candidate`, `evaluating`) and keyboard shortcuts (Space to toggle mic, Cmd+Enter to submit).
- **TPO Dashboard 4x Performance Bottleneck & Broken Heatmap**: The TPO command center called `predict_student_employability()` for every student **4 separate times** (once per endpoint: overview, students-with-scores, alerts, branch-breakdown) totaling 104 ML predictions on every page load for 26 students. Fixed by: 1) Adding a 30-second TTL in-memory `_tpo_scores_cache` that all four endpoints share; 2) Consolidating score computation into `_compute_all_student_scores()` called once per 30-second window; 3) Adding `_invalidate_tpo_cache()` after CSV uploads. Additionally, the frontend called `/api/tpo/skill-heatmap` but the backend only had `/api/tpo/skill-deficit-heatmap` — heatmap was silently empty. Fixed by adding an alias endpoint. CSV upload success handler called nonexistent functions `loadOverview()`, `loadStudents()`, etc. — fixed to call `loadAll()`.
- **TPO Dashboard Logical Improvements**: 1) Quick stats now shows Placement Rate %, Avg Batch CGPA, and Total Certifications count; 2) Student modal expanded from 3 to 4 KPI columns (CGPA, Score, Interviews, Avg Skill) plus strong/weak skills breakdown, projects display, and internship/certification badges; 3) Vulnerable students table now sorts worst-first and has functional "Schedule Counseling" buttons wired to `triggerTpoAction`; 4) Skills in modal now color-coded by proficiency (green ≥7, amber ≥5, red <5).
- **UI Theme Unification & Broadsheet Minimal System**: Unified all 5 portals (`student`, `tpo`, `interview`, `login`, `signup`) into the Broadsheet Minimal design system (warm ivory parchment `#FBF9F5`, Newsreader optical serif typography, carbon ink `#1E1E1E`, hairline borders `#E5E0D5`, and terracotta `#E0531C` accents). Converted `static/interview/index.html` from dark obsidian neon to Broadsheet Minimal (custom `interview-broadsheet` Monaco editor theme, terracotta/emerald Web Audio canvas visualizer gradients, and unified Broadsheet topbar). Added smooth staggered entrance cascades and tactile micro-interactions.
- **macOS Apple Silicon Joblib Loky Semaphore Deadlock**: In `ml/model_trainer.py`, nested parallelism with `StackingClassifier(n_jobs=-1)` wrapping base estimators that also had `n_jobs=-1` caused POSIX semaphore deadlocks (`__semwait_signal`) under joblib loky on Apple Silicon macOS. Resolved by setting `StackingClassifier(n_jobs=1)` so folds run sequentially while each estimator leverages all CPU cores, executing training in under 22 seconds without deadlocks.
